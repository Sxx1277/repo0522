研究内容 · 背景及问题

从传统“录像猫眼”升级为 AI“识别猫眼”，实现访客鉴别 + 环境安防 + 远程联控

研究背景 主要工作

背景与主要研究内容

  • 痛点：传统猫眼视野窄、无法主动识别访客身份
  • 方向：由“录像”→“识别”，差异化响应熟人/陌生人
  • 双芯片：STM32F103C8T6 主控 + K210（YOLOv2）协处理
  • 传感联动：DHT11 / MQ-2 / 火焰传感器 + ISD1820 语音
  • 物联：ESP8266 + MQTT → OneNet + 手机 APP
待解决问题 设计目标

问题与目标

  • 嵌入式资源受限下的精度与功耗平衡
  • 单一监控无法覆盖火灾等室内风险
  • 目标① 人脸识别准确率 ≥ 98%
  • 目标② 异常报警触发率 100%
  • 构建“感知—决策—执行—云端”闭环安防

系统架构与模块划分

双芯片分层架构：STM32 控制层 + K210 AI 层 + 环境感知 + OneNet 远程交互

图2-1 整体设计框图（感知/控制/执行/远程四层）

核心控制层

以 STM32F103C8T6 为主控核心，负责传感器数据采集（环境监测）、执行机构控制（舵机模拟开门、声光报警）及 K210 / ESP8266 多路串口调度。

USART1 → K210 USART2 → ESP8266 ADC / I2C / PWM

AI 视觉感知层

采用 K210 边缘侧计算芯片，内嵌轻量化 YOLOv2 目标检测算法，实现实时人脸捕获与离线快速识别，识别结果经串口回传主控决策。

KPU 硬件加速 320×240 推理

环境监测与物联联动

集成 DHT11 温湿度、MQ-2 烟雾、FC-37 火焰传感器多路采集；通过 ESP8266 + MQTT 与 OneNet 平台保持双向长连接，支持远程开门与阈值下发。

自动/手动双模式 本地 + 云端闭环

软件流程与算法核心

主程序状态机 + YOLOv2/KPU 子程序 + 环境异常中断优先响应

主流程 · 图4-1
主程序状态机逻辑
Init：GPIO / TIM / USART / ADC / I2C 初始化
while(1)：传感轮询 · K210 帧 · MQTT 指令
分支：熟人开门 / 陌生人告警 / 环境超限上云
  • 串口中断接收 K210 识别结果
  • 与 ADC/GPIO 采集并行调度
子流程 · 图4-2
AI 识别子程序（YOLOv2）
320×240 帧缓冲采集
KPU 推理 → NMS 筛选
特征比对 → UART 回传 FACE:ID
  • 余弦相似度 > 0.7：白名单放行
  • 否则 ID=0，触发陌生人告警
子流程 · 图4-3
异常中断响应机制

火焰/烟雾超阈立即挂起主流程，

优先蜂鸣器 + LED + ISD1820 播报，

JSON 经 MQTT 紧急上报 OneNet。
